## 遗留给 L4 的线索

1. **先阻断任何生产写发布。** L3C-01 是直接可复现的意外写入口；L3C-02 会绕过 audited variant fail-closed；L3C-03 破坏不可逆 channels 所依赖的 durable baseline 前提。三项均应在 L4 合并态 gate 前修复并做正样本红／绿对照。
2. **共享 contract 仍有跨语言未闭环项。** 平台 gate 新 code 未进入 error catalog；extended UNC 不在 canonical vectors；substate 没有冻结完整 record schema，导致 absent offset 和 replay validation 漂移。修 Python 时应同步检查 JS／contract，避免只让一侧变绿。
3. **测试假绿的具体接缝。** `test_contract_consumption.py` 对 schema／hash 的消费是真实有效的，但不证明生产分发；建议 L4 必跑 fresh wheel。`test_feature_vectors.py` 的 partial replay 正例与 JS contract 冲突，应翻转为 known-bad 正样本。裸非 TTY 测试必须带 `--binary`／`--json` 才能覆盖真实分发分支。
4. **平台 gate 的覆盖范围需由 L4 明确记录。** 当前 gate 只保护 target binary 写入口 `write_features` 与 `restore_snapshot`；snapshot save／rm、lock cleanup、store manifest 写不受 gate。JS 也是如此。如果 `production_write_gate` 的定义是“仅 binary mutation”，应在 contract 明写；若指所有 mutating command，则两实现都缺 gate。
