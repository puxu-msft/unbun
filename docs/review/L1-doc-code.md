## 主会话独立复核（verifying-authoritative-claims）

- **L1B-01 Blocker 已独立确认成立**。主会话 grep 全仓库 `production_write_gate` 的使用：JS 仅 `lib/patch/store/lineage.mjs:32` 把 `status` 读成 `productionWriteGate` 字段、无任何条件分支；Python `lineage.py:46-67` 把它加载进 `PlatformGate` 后同样不作拒绝。唯一的平台拒绝是 `platform_write_unsupported`（平台 key **完全缺失**时抛出），而 `contract/vectors/platform-writes-v1.json` 里 windows(`disabled-pending-runtime`)/macos(`disabled-not-proven`) 的 key 都存在、gate 仅标 disabled，因此写路径照常放行。文档所称「production gate 禁用」与代码行为相反，属假 gate，确认为 🔴 Blocker。

## 遗留给 L3 复核的线索

1. `lib/patch/transaction/transaction.mjs:165-304` 与 Python `python/cc-patch/src/cc_patch/orchestrate.py:482-522` 的平台 gate 缺失不只是文档问题：需在 Linux、Windows、macOS 的真实 CLI 层分别验证写入拒绝、baseline 不创建、目标 bytes 不变和退出码稳定性；修复时避免只在 TUI 或 status 层检查。
2. `cli.mjs:463-504` 的 `cc run` 参数解析还吞掉未识别的 `--flag`，而不是 fail-loud。L3 应构造真实 probe，断言 `--` 后的带值 flag、裸 flag、`--` 分隔符与路径中以连字符开头的参数均逐字节抵达 child argv。
3. `lib/bun-binary.mjs:3` 对 `lib/patch/io/raw-reader.mjs` 的反向层级依赖是否会把 patch 运行时约束带入通用解析层，需要在 L3 的可维护性/测试隔离评审中判定；本线只确认 ARCHITECTURE 的「无依赖」描述不正确。
4. `lib/module-graph.mjs:19-31,84-153` 的格式常量由 fail-loud 自证保护，但 L3 应审查自证不变量是否足以排除未来 Bun 格式的误解析，尤其是 `LOADER` enum 演进和 trailer 候选选择。
