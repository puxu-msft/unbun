# L2-A — 假绿检测 / 独立证伪

> 执行者：verifier（独立证伪，L2-A 分派线）。范围：`contract/golden`、`contract/vectors/**`、`test/interop/**`、`docs/dual-implementation-acceptance.md` 声称的发布 gate。方法：先从冻结 spec（`docs/dual-implementation-spec.md` 第 10、11 节）独立推导验收判据，再对照实现/测试，最后实测运行（含正向证伪注入）。

## 总体判断

**双实现「等价性」证据链本身设计得相当审慎，多数假绿模式已被工程性防范**，但发布 acceptance 文档中至少一条被列为 `PASS` 的关键 gate（`runtime-oracle.test.mjs` 的「双实现均通过真实 gpt 子请求 oracle」）**在本次独立复跑中实测失败**，且失败原因（clean 基线因未登录而拒绝执行，非双实现代码问题）说明该 gate 从未在当前环境下被验证过、其「PASS」结论不可复现。此前发现一处**跨实现测试覆盖不对称**：JS 侧对 `agent-model` 的「receiver identity 必须匹配才允许 replay」有专门负测试，而 Python 缺少等价校验；现已由 Python 侧补齐 receiver 字段采集、回放 identity 校验与 forged-swap 负测试。当前生产写路径仍仅含单一 agent-model 站点，但多站点 receiver 场景已获得直接回归覆盖。

对「golden 独立性」「frozen vectors 独立性」「interop 真双向」三项重点证伪目标，本次核实结果总体正面：golden 字节确有可信的历史来源审计记录且 SHA256 冻结、`_generate.py` 不参与日常测试（正向复现校验：手工翻转 clean golden 一个字节后，`bun test test/contract/vector-integrity.test.mjs test/patch/agent-model.test.mjs test/patch/source-exec.test.mjs` 立即产生 5 个失败，证明该 golden 被真实消费而非摆设）；`test/interop/**` 中的 `alternating-cli.test.mjs`、`baseline-replay.test.mjs`、`differential.test.mjs`、`public-store-assets.test.mjs` 均采用 `[['javascript','python'],['python','javascript']]` 双向交替的参数化用例，且底层跑的是两个真实公开 CLI 子进程（`bun cli.mjs cc ...` 与 `uv run ccpatch ...`），不是同实现自测；`exact-replay-harness.test.mjs` 让 JS PoC 与 Python PoC 各自独立产出 `expected` 字节，再互相验证对方产出的字节，形成真正跨语言互证而非同源 roundtrip。

因此本层结论是：**「双实现等价」的证据链框架本身可信，但至少一个被文档标记为 PASS 的发布 gate 无法在本环境复现（Blocker 级别的可信度问题，不是代码等价性问题），加上一处真实存在但当前不可达的跨实现测试不对称（Major，未来若开放多站点场景会成为假绿）**。总体评分：证据链设计 8/10，acceptance 文档「已通过」声明的可信度 5/10（因至少一条关键 gate 不可复现且未见环境降级处理）。

## 遗留给 L3/L4 的线索
